## §3 · Discrepancia `gp_roles_proyecto_c` (tabla 5) — CONGELADA

> **ACTUALIZACIÓN 16-nov (auditoría en vivo) — discrepancia DISUELTA:** el inventario de
> `public` devuelve **solo 4 tablas `gp_*`** (`gp_estados_proyecto_c`, `gp_tipos_proyecto_c`,
> `gp_estados_ejecucion_c`, `gp_prioridades_c`). **`gp_roles_proyecto_c` NO existe**, así que
> el supuesto "9 columnas en vivo vs 10 en `0001`" no tenía objeto: se creará desde `0001`
> tal cual (10 columnas) cuando llegue su turno, y `20261115_0008` deja de ser necesario
> (queda solo como red de seguridad idempotente). El resto de este apartado se conserva
> como registro histórico de la decisión y de las queries de contraste.

**Estado:** la tabla **existe EN VIVO** en Supabase con **9 columnas** (informe del
responsable; cuál falta o difiere aún no contrastado en el repo), mientras que la
fuente `0001` (L82-94) la define con **10 columnas** + `UNIQUE(codigo)`:

| # | Columna según `0001` | udt_name esperado |
|---|---|---|
| 1 | `id` (PK, default `gen_random_uuid()`) | uuid |
| 2 | `codigo` NOT NULL | text |
| 3 | `nombre` NOT NULL | text |
| 4 | `descripcion` | text |
| 5 | `permisos` NOT NULL DEFAULT `'{}'` | jsonb |
| 6 | `activo` NOT NULL DEFAULT `true` | bool |
| 7 | `orden` DEFAULT `0` | int4 |
| 8 | `metadata` NOT NULL DEFAULT `'{}'` | jsonb |
| 9 | `created_at` NOT NULL DEFAULT `now()` | timestamptz |
| 10 | `updated_at` NOT NULL DEFAULT `now()` | timestamptz |
| — | `UNIQUE(codigo)` → `gp_roles_proyecto_c_codigo_key` | constraint |

Seed de `0001` (L185): **6 roles** — administrador, gestor, coordinador,
supervisor, colaborador, lector.

**Decisión (responsable, 14-nov):** tabla **CONGELADA** — no se crea, no se
duplica, no se altera hasta resolver la discrepancia. Ningún SQL la toca.
