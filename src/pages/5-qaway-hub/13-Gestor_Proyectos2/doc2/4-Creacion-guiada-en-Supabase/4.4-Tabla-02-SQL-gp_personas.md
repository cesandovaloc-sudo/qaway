# 4.4 · TABLA 02 (SQL) — `gp_personas`

**Ejercicio 2 de 2.** Aquí se prueba el procedimiento completo: claves foráneas al Hub, índices,
trigger y RLS con aislamiento por empresa.

- **Qué es:** personas del dominio (quien trabaja en los proyectos). No es una tabla de cuentas.
- **Dependencias:** `public.tenants` (empresa) y `public.users` (cuenta, opcional). Ambas existen:
  verificado en `4.1`.
- **No depende de ninguna tabla `gp_*`**, por eso puede ser la segunda.
- **Justificación:** doc 3.6 §7.2 — sustituye a `gp_persona_cuentas_r` (eliminada). `user_id`
  opcional permite registrar a alguien sin cuenta (un contacto externo).
- **Paridad:** idéntica a `20261112_0002_gp_entidades_principales.sql`.

## Bloque 1 · Estructura, índices y trigger

```sql
-- Función de updated_at del dominio (el Hub no tiene una genérica en la BD central)
create or replace function public.gp_touch_updated_at()
returns trigger
language plpgsql
set search_path = public
as $$
begin
  new.updated_at = now();
  return new;
end;
$$;

create table if not exists public.gp_personas (
  id uuid primary key default gen_random_uuid(),
  empresa_id uuid not null
    references public.tenants(id) on update cascade on delete restrict,
  user_id uuid
    references public.users(id) on update cascade on delete set null,
  nombres text not null,
  apellidos text,
  nombre_completo text generated always as
    (trim(coalesce(nombres,'') || ' ' || coalesce(apellidos,''))) stored,
  tipo_documento text,
  numero_documento text,
  correo text,
  telefono text,
  cargo text,
  activo boolean not null default true,
  metadata jsonb not null default '{}'::jsonb,
  legacy_source_id text,
  is_deleted boolean not null default false,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  created_by uuid,
  updated_by uuid
);

create index if not exists idx_gp_personas_empresa
  on public.gp_personas (empresa_id);
create index if not exists idx_gp_personas_user
  on public.gp_personas (user_id);
create index if not exists idx_gp_personas_documento
  on public.gp_personas (empresa_id, tipo_documento, numero_documento)
  where numero_documento is not null;

-- Una persona = una cuenta como máximo dentro de la misma empresa
create unique index if not exists uq_gp_personas_empresa_user
  on public.gp_personas (empresa_id, user_id)
  where user_id is not null;

-- El mismo documento no puede repetirse dos veces en la misma empresa
create unique index if not exists uq_gp_personas_empresa_documento
  on public.gp_personas (empresa_id, tipo_documento, numero_documento)
  where numero_documento is not null and is_deleted = false;

create trigger set_gp_personas_updated_at
  before update on public.gp_personas
  for each row execute function public.gp_touch_updated_at();
```

### Por qué así

| Elemento | Motivo |
|---|---|
| `empresa_id ... references public.tenants` | La empresa la administra el Hub. `on delete restrict`: no se puede borrar una empresa con personas colgando. |
| `user_id ... on delete set null` | Si se elimina la cuenta, la persona histórica se conserva sin cuenta. No se pierde el registro de proyectos. |
| `nombre_completo ... generated always ... stored` | Se calcula en la base: nadie puede guardar un valor distinto del real. |
| Índices únicos **parciales** (`where ...`) | Solo aplican cuando el dato existe: varios contactos sin cuenta o sin documento son válidos. |
| `is_deleted` | Borrado lógico: los proyectos no deben perder su responsable. |
| `gp_touch_updated_at()` | Se crea una función propia en lugar de reutilizar una que en la BD central no existe. |

## Bloque 2 · RLS, políticas y permisos

```sql
alter table public.gp_personas enable row level security;

revoke all on public.gp_personas from anon;
grant select, insert, update, delete on public.gp_personas to authenticated;

-- SELECT: solo personas de mi empresa
create policy gp_personas_select on public.gp_personas
  for select to authenticated
  using (
    public.is_platform_admin()
    or (empresa_id = public.get_auth_tenant_id() and public.is_tenant_member())
  );

-- INSERT: solo dentro de mi empresa y siendo admin de la empresa
create policy gp_personas_insert on public.gp_personas
  for insert to authenticated
  with check (
    public.is_platform_admin()
    or (empresa_id = public.get_auth_tenant_id() and public.is_tenant_admin())
  );

-- UPDATE: misma condición, y no se puede "mover" la fila a otra empresa
create policy gp_personas_update on public.gp_personas
  for update to authenticated
  using (
    public.is_platform_admin()
    or (empresa_id = public.get_auth_tenant_id() and public.is_tenant_admin())
  )
  with check (
    public.is_platform_admin()
    or (empresa_id = public.get_auth_tenant_id() and public.is_tenant_admin())
  );

-- DELETE: nadie borra personas; se usa is_deleted = true
create policy gp_personas_delete on public.gp_personas
  for delete to authenticated
  using (public.is_platform_admin());
```

**Clave del diseño:** `empresa_id = get_auth_tenant_id()` en *todas* las políticas. Pertenecer a una
empresa **no** da acceso a otra. El `with check` del UPDATE impide el ataque clásico de cambiar
`empresa_id` para "mover" una fila a una empresa ajena.

**Pendiente anotado (no aplica ahora):** cuando exista el slug `gestor-proyectos` en `app_catalog`,
`is_tenant_admin()` se sustituye por `public.user_app_role('gestor-proyectos') in ('admin','editor')`.

### Prueba de aislamiento entre empresas

Averigua dos usuarios de **empresas distintas** (`select id, tenant_id from public.users limit 5;`)
y sustitúyelos:

```sql
begin;
set local role authenticated;
set local request.jwt.claims = '{"sub":"<UUID_USUARIO_EMPRESA_A>","role":"authenticated"}';
select count(*) from public.gp_personas where empresa_id = '<UUID_EMPRESA_B>';  -- debe dar 0
rollback;
```

**Debe dar 0** aunque consultes directamente el `empresa_id` ajeno: la RLS filtra antes.
