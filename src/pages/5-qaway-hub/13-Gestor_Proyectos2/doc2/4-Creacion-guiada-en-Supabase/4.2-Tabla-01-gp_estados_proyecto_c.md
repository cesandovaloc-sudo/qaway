# 4.2 · Tabla 01 — `gp_estados_proyecto_c`

**Qué es:** un catálogo. No guarda proyectos, guarda **los estados válidos** que un proyecto puede
tener (`planificacion`, `en_curso`, `pausado`, `completado`, `cancelado`). Existe para que en
`gp_proyectos.estado_codigo` no se pueda escribir cualquier texto: solo un valor de esta lista.

**Por qué primero:** no depende de ninguna otra tabla. Es la base de todo lo que viene.

---

## Paso 1 · Crear la tabla

Pegar en **SQL Editor → Run**:

```sql
create table if not exists public.gp_estados_proyecto_c (
  id           uuid primary key default gen_random_uuid(),  -- identidad técnica, opaca
  codigo       text not null unique,                        -- valor que se guarda en otras tablas
  nombre       text not null,                               -- etiqueta visible al usuario
  descripcion  text,                                        -- texto libre, opcional
  activo       boolean not null default true,               -- permite retirar sin borrar
  orden        integer default 0,                           -- orden de presentación en listas
  metadata     jsonb not null default '{}'::jsonb,           -- espacio para crecer sin migrar
  created_at   timestamptz not null default now(),
  updated_at   timestamptz not null default now()
);
```

### Por qué está escrita así (para el curso)

| Elemento | Motivo |
|---|---|
| `uuid primary key default gen_random_uuid()` | El id no se escribe a mano ni se reutiliza. Nunca cambia. `gen_random_uuid()` viene de `pgcrypto`, incluida por defecto en Supabase. |
| `codigo text not null unique` | Este es el valor de negocio (`en_curso`). Único, para que no existan dos "En curso". |
| `activo` en vez de `DELETE` | Un estado que ya no se usa se desactiva; así los proyectos históricos no quedan huérfanos. |
| `metadata jsonb` | Evita migrar la tabla por cada atributo nuevo (por ejemplo, un color o un ícono). |
| `timestamptz` y no `timestamp` | Guarda zona horaria. Supabase trabaja en UTC; `timestamptz` evita el clásico error de "una hora corrida". |
| `create table if not exists` | Si lo ejecutas dos veces, no falla. |

---

## Paso 2 · Verificar que existe

```sql
-- ¿La tabla quedó creada con sus 9 columnas?
select column_name, data_type, is_nullable, column_default
from information_schema.columns
where table_schema = 'public' and table_name = 'gp_estados_proyecto_c'
order by ordinal_position;
```

**Debe salir 9 filas:** `id, codigo, nombre, descripcion, activo, orden, metadata, created_at, updated_at`.

---

## Paso 3 · Cargar los estados

```sql
insert into public.gp_estados_proyecto_c (codigo, nombre, orden) values
  ('planificacion', 'Planificación', 1),
  ('en_curso',      'En curso',      2),
  ('pausado',       'Pausado',       3),
  ('completado',    'Completado',    4),
  ('cancelado',     'Cancelado',     5)
on conflict (codigo) do nothing;
```

`on conflict (codigo) do nothing` = si lo corres otra vez, actualiza nada y no falla.

### Verificación

```sql
select codigo, nombre, activo from public.gp_estados_proyecto_c order by orden;
```

**Debe salir 5 filas.**

---

## Si algo falla

| Mensaje | Significado |
|---|---|
| `permission denied for schema public` | Estás corriendo el SQL con un rol equivocado; usa el SQL Editor del proyecto (rol `postgres`). |
| `function gen_random_uuid() does not exist` | Falta `create extension if not exists pgcrypto;`. En Supabase ya viene; si no, ejecútalo antes. |
| `relation "gp_estados_proyecto_c" already exists` con `if not exists` | No debería ocurrir; revisa que copiaste la línea completa del `create table`. |
| `duplicate key value violates unique constraint` en el insert | Ya había filas con ese `codigo`. Usa el `on conflict` incluido. |
