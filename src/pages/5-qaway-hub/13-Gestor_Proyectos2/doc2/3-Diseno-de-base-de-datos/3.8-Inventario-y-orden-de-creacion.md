## 3 · Matriz de dependencias y orden de creación

### 3.1 · Por qué este orden

El orden **es el de los archivos de migración**, que ya respeta la topología (cada `CREATE` referencía solo tablas creadas antes, en el mismo archivo o en archivos previos):

```
[Capa 0 · YA EXISTENTE]  tenants · users · auth · user_app_roles
                         gestor_proyectos · gestor_cronograma_items (+02,+04) · gestor_unidades
        │
Paso 1   0001_gp_catalogos_base.sql            → 12 catálogos + 5 seeds
        │
Paso 2   0002_gp_entidades_principales.sql     → gp_proyectos, gp_personas, gp_fases,
        │                                        gp_nodos_edt, gp_tareas, gp_equipos
        │                                        (requiere: 0001 + gestor_unidades + tenants/users)
Paso 3   0003_gp_entidades_operativas...sql    → 8 operativas/control + 8 _r
        │                                        (requiere: 0002 + gestor_unidades)
Paso 4   0004_gp_funciones_triggers_rls...sql  → helpers RLS, triggers, RLS (69 políticas),
        │                                        índices (requiere: 0001-0003 + user_app_roles)
Paso 5   backfill/0100_backfill_idempotente.sql → migración de datos (requiere: TODO lo anterior;
                                                 service_role; prevalidaciones A-6)
```
