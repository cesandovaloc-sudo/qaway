### 1.2 Las dos inconsistencias resueltas expresamente

1. **`0007` estaba fuera de la secuencia de 6.3.** En `6.1` (L15/L95/L130-134) figura como pendiente y **requerido** para la integración del selector de prioridad, y el FK `gp_tareas.prioridad_codigo → gp_prioridades_c(codigo)` (`0002` L199) no puede crearse sin esa tabla. **Resolución:** `0007` entra en FASE 2, antes de `0002`. (Nota: `0001` también crea la tabla; `0007` re-confirma idempotentemente la forma exacta aprobada en el paquete `5.5` y su seed con `urgente`.)
2. **`0002` y `0003` también estaban fuera de toda secuencia anterior** (la cadena de 6.3 decía `0006a → 0005 → 0006b → 0004 → 0008 → 0009 → 0010`). Eso era inviable: la §1 de `0010` **aborta** si no existen `gp_proyectos`, `gp_personas` y `gp_proyecto_miembros_r` — que hoy no existen en vivo. **Resolución:** FASE 3 incorpora `0002 → 0003 → 0004` en su posición real (después de los catálogos que alimentan sus FK, antes de la RPC).

### 1.3 ¿Por qué `0008` va ANTES de `0003`? (inconsistencia adicional resuelta)

El FK `gp_proyecto_miembros_r.rol_proyecto_codigo → gp_roles_proyecto_c(codigo)` (`0003` L221) exige `UNIQUE(codigo)` en `gp_roles_proyecto_c`. **Actualizado 16-nov:** esa tabla **no existe en vivo** (auditoría `7-Bitacoras/20261116-…`), la crea `0001` con `UNIQUE(codigo)` incluido, y `0008` ya no es necesario para desbloquear `0003`. Se conserva solo como red de seguridad idempotente (aborta limpio si la tabla no existe o si hubiera duplicados).

```sql
CREATE OR REPLACE FUNCTION public.gp_set_updated_at()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$;

-- Aplicar trigger updated_at a tablas con columna updated_at (idempotente vía DO)
DO $$
DECLARE r record;
BEGIN
  FOR r IN
    SELECT c.table_name
    FROM information_schema.columns c
    WHERE c.table_schema = 'public'
      AND c.table_name LIKE 'gp_%'
      AND c.column_name = 'updated_at'
  LOOP
    IF NOT EXISTS (
      SELECT 1 FROM pg_trigger t
      JOIN pg_class cl ON cl.oid = t.tgrelid
      JOIN pg_namespace n ON n.oid = cl.relnamespace
      WHERE t.tgname = ('trg_' || r.table_name || '_updated_at')
        AND cl.relname = r.table_name
        AND n.nspname = 'public'
        AND NOT t.tgisinternal
    ) THEN
      EXECUTE format('CREATE TRIGGER %I BEFORE UPDATE ON public.%I FOR EACH ROW EXECUTE FUNCTION public.gp_set_updated_at()',
        'trg_' || r.table_name || '_updated_at', r.table_name);
    END IF;
  END LOOP;
END $$;
```

```sql
-- ==============================================================================
-- §2 · gp_rol_proyecto_actual — ROL DEL USUARIO EN EL PROYECTO (solo lectura)
-- ==============================================================================
CREATE OR REPLACE FUNCTION public.gp_rol_proyecto_actual(p_proyecto_id uuid)
RETURNS text
LANGUAGE plpgsql
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  v_user    uuid;
  v_tenant  uuid;
  v_empresa uuid;
  v_borrado boolean;
  v_persona uuid;
  v_rol     text;
BEGIN
  v_user := auth.uid();
  IF v_user IS NULL THEN
    RETURN NULL; -- sin sesión: fail-closed (la UI muestra "sin sesión/consulta")
  END IF;

  SELECT empresa_id, is_deleted INTO v_empresa, v_borrado
    FROM public.gp_proyectos
   WHERE id = p_proyecto_id;
  IF NOT FOUND OR v_borrado THEN
    RETURN NULL; -- proyecto inexistente/eliminado: sin rol (no revela existencia)
  END IF;

  -- Guard de tenant: el usuario debe pertenecer a la EMPRESA del proyecto.
  v_tenant := public.get_auth_tenant_id();
  IF v_tenant IS NULL OR v_tenant <> v_empresa THEN
    RETURN NULL;
  END IF;

  -- Persona del usuario en esa empresa (gp_personas.user_id, 0002 L86/L108).
  SELECT id INTO v_persona
    FROM public.gp_personas
   WHERE user_id = v_user
     AND empresa_id = v_empresa
     AND is_deleted = false
   LIMIT 1;
  IF v_persona IS NULL THEN
    RETURN NULL;
  END IF;

  -- Membresía ACTIVA del proyecto (0003 L216-232).
  SELECT rol_proyecto_codigo INTO v_rol
    FROM public.gp_proyecto_miembros_r
   WHERE proyecto_id = p_proyecto_id
     AND persona_id  = v_persona
     AND empresa_id  = v_empresa
     AND estado      = 'activo'
   LIMIT 1;

  RETURN v_rol; -- NULL ⇒ sin rol ⇒ la UI deriva "solo consulta" (fail-closed)
END;
$$;

-- ==============================================================================
-- §3 · gp_cambiar_estado_proyecto — ÚNICO CAMINO DE CAMBIO (UPDATE + AUDITORÍA
--      ATÓMICOS). Espejo exacto del núcleo de gpCicloVidaService (validarAccion).
-- ==============================================================================
CREATE OR REPLACE FUNCTION public.gp_cambiar_estado_proyecto(
  p_proyecto_id   uuid,
  p_estado_nuevo  text,
  p_motivo        text DEFAULT NULL
)
RETURNS jsonb
LANGUAGE plpgsql
VOLATILE
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  v_user               uuid;
  v_tenant             uuid;
  v_actual             text;
  v_empresa            uuid;
  v_borrado            boolean;
  v_accion             text;
  v_motivo_obligatorio boolean;
  v_motivo             text;
  v_persona            uuid;
  v_rol                text;
  v_permisos           jsonb;
BEGIN
  -- 1) Sesión obligatoria (fail-closed).
  v_user := auth.uid();
  IF v_user IS NULL THEN
    RAISE EXCEPTION 'PERMISO_INSUFICIENTE: sin sesión activa (auth.uid() NULL). Inicia sesión en Qaway Hub para cambiar el estado del proyecto.';
  END IF;

  -- 2) Proyecto EXISTENTE + bloqueo de fila (FOR UPDATE) hasta el fin de la fn.
  SELECT estado_codigo, empresa_id, is_deleted
    INTO v_actual, v_empresa, v_borrado
    FROM public.gp_proyectos
   WHERE id = p_proyecto_id
   FOR UPDATE;
  IF NOT FOUND OR v_borrado THEN
    RAISE EXCEPTION 'TRANSICION_INVALIDA: proyecto no encontrado o eliminado (gp_proyectos.id = %).', p_proyecto_id;
  END IF;

  -- 3) Guard de tenant.
  v_tenant := public.get_auth_tenant_id();
  IF v_tenant IS NULL OR v_tenant <> v_empresa THEN
    RAISE EXCEPTION 'PERMISO_INSUFICIENTE: el proyecto pertenece a otra empresa (guard de tenant get_auth_tenant_id).';
  END IF;

  -- 4) Destino activo en el catálogo (gp_estados_proyecto_c — 0004 deja RLS
  --    select para todos; aquí es servidor, sin RLS: validación explícita).
  IF NOT EXISTS (
    SELECT 1 FROM public.gp_estados_proyecto_c
     WHERE codigo = p_estado_nuevo AND activo = true
  ) THEN
    RAISE EXCEPTION 'TRANSICION_INVALIDA: el estado destino "%" no existe o no está activo en gp_estados_proyecto_c.', p_estado_nuevo;
  END IF;

  -- 5) Estado actual NULL ⇒ "Sin clasificar" (B-8): NO transiciona.
  IF v_actual IS NULL THEN
    RAISE EXCEPTION 'TRANSICION_INVALIDA: el proyecto está "Sin clasificar" (estado NULL, B-8): asigna su estado en la migración/cutover antes de acciones de dirección.';
  END IF;

  -- 6) Transición aprobada (mapa EXACTO de la Etapa 6.3, igual a
  --    TRANSICIONES_VALIDAS del servicio). Sin match ⇒ inválida (incluye
  --    destino = origen, que nunca está listado).
  SELECT t.accion, t.motivo_obligatorio
    INTO v_accion, v_motivo_obligatorio
  FROM (VALUES
    ('planificacion','en_curso',     'iniciar',  false),
    ('en_curso',     'pausado',      'pausar',   false),
    ('pausado',      'en_curso',     'reanudar', false),
    ('en_curso',     'completado',   'completar', true),
    ('pausado',      'completado',   'completar', true),
    ('planificacion','cancelado',    'cancelar',  true),
    ('en_curso',     'cancelado',    'cancelar',  true),
    ('pausado',      'cancelado',    'cancelar',  true),
    ('completado',   'en_curso',     'reabrir',   true),  -- reapertura → en_curso
    ('cancelado',    'planificacion','reabrir',   true)   -- reapertura → planificacion
  ) AS t(estado_origen, estado_destino, accion, motivo_obligatorio)
   WHERE t.estado_origen  = v_actual
     AND t.estado_destino = p_estado_nuevo;

  IF v_accion IS NULL THEN
    RAISE EXCEPTION 'TRANSICION_INVALIDA: la transición "%" → "%" no es válida según las reglas aprobadas (Etapa 6.3).', v_actual, p_estado_nuevo;
  END IF;

  -- 7) Motivo obligatorio para completar / cancelar / reabrir.
  v_motivo := CASE WHEN p_motivo IS NULL THEN NULL ELSE btrim(p_motivo) END;
  IF v_motivo = '' THEN v_motivo := NULL; END IF;
  IF v_motivo_obligatorio AND v_motivo IS NULL THEN
    RAISE EXCEPTION 'MOTIVO_REQUERIDO: la acción "%" exige un motivo obligatorio (queda registrado en gp_eventos_auditoria).', v_accion;
  END IF;

  -- 8) AUTORIZACIÓN (fail-closed, sin confiar en la UI):
  --    a) plataforma (gp_is_platform_admin, 0004) ⇒ todas;
  --    b) admin de la app en el Hub (user_app_role('gestor-proyectos')='admin') ⇒ todas;
  --    c) resto: SOLO con rol ACTIVO del proyecto cuyo permiso de la acción esté
  --       a 'true' en gp_roles_proyecto_c.permisos. Pertenecer NO es permiso.
  IF COALESCE(public.gp_is_platform_admin(), false) OR COALESCE(public.user_app_role('gestor-proyectos'), '') = 'admin' THEN
    v_persona := NULL; -- la auditoría registra actor_user_id (admin sin persona)
  ELSE
    SELECT id INTO v_persona
      FROM public.gp_personas
     WHERE user_id = v_user
       AND empresa_id = v_empresa
       AND is_deleted = false
     LIMIT 1;
    IF v_persona IS NULL THEN
      RAISE EXCEPTION 'PERMISO_INSUFICIENTE: no estás registrado como persona de esta empresa (gp_personas.user_id) y no tienes rol de plataforma/admin de empresa.';
    END IF;

    SELECT rol_proyecto_codigo INTO v_rol
      FROM public.gp_proyecto_miembros_r
     WHERE proyecto_id = p_proyecto_id
       AND persona_id  = v_persona
       AND empresa_id  = v_empresa
       AND estado      = 'activo'
     LIMIT 1;
    IF v_rol IS NULL THEN
      RAISE EXCEPTION 'PERMISO_INSUFICIENTE: la pertenencia al proyecto NO otorga permisos administrativos (sin rol activo en gp_proyecto_miembros_r).';
    END IF;

    -- `permisos` jsonb (0001 L87). Si la columna falta en vivo (discrepancia
    -- 9↔10) o el seed 0008 no está aplicado ⇒ error EXPLICÍTO, nunca falso OK.
    BEGIN
      SELECT permisos INTO v_permisos
        FROM public.gp_roles_proyecto_c
       WHERE codigo = v_rol AND activo = true;
      IF NOT FOUND THEN
        RAISE EXCEPTION 'PERMISO_INSUFICIENTE: el rol "%" no existe o está inactivo en gp_roles_proyecto_c — aplica el seed 20261115_0008.', v_rol;
      END IF;
    EXCEPTION
      WHEN undefined_column THEN
        RAISE EXCEPTION 'PERMISO_INSUFICIENTE: gp_roles_proyecto_c no tiene la columna permisos (discrepancia 9↔10 columnas) — aplica 20261115_0008.';
    END;

    IF COALESCE(v_permisos ->> v_accion, 'false') <> 'true' THEN
      RAISE EXCEPTION 'PERMISO_INSUFICIENTE: el rol "%" no permite la acción "%" (gp_roles_proyecto_c.permisos).', v_rol, v_accion;
    END IF;
  END IF;

  -- 9) UPDATE del estado (fila YA bloqueada con FOR UPDATE desde el paso 2).
  UPDATE public.gp_proyectos
     SET estado_codigo = p_estado_nuevo,
         updated_at    = now()
   WHERE id = p_proyecto_id;

  -- 10) AUDITORÍA en la MISMA transacción (0003 L172-186): STATE_CHANGE con
  --     motivo en payload_despues (contrato leído por listarHistorialEstado).
  INSERT INTO public.gp_eventos_auditoria
    (empresa_id, proyecto_id, entidad, entidad_id, accion,
     payload_antes, payload_despues, actor_user_id, actor_persona_id, origen)
  VALUES
    (v_empresa,
     p_proyecto_id,
     'gp_proyectos',
     p_proyecto_id,
     'STATE_CHANGE',
     jsonb_build_object('estado_codigo', v_actual),
     jsonb_build_object('estado_codigo', p_estado_nuevo, 'accion', v_accion, 'motivo', v_motivo),
     v_user,
     v_persona,
     'app');

  -- 11) Resultado contractual (el frontend mapea estos campos en su modelo local).
  RETURN jsonb_build_object(
    'proyecto_id',      p_proyecto_id,
    'estado_anterior',  v_actual,
    'estado_nuevo',     p_estado_nuevo,
    'accion',           v_accion,
    'motivo',           v_motivo
  );
END;
$$;
```

### 4.12 · FASE 4 (opcional) — `20261115_0011_gp_proyectos_estado_guard_opcional.sql`

```sql
-- ==============================================================================
-- GESTOR DE PROYECTOS 2 · ETAPA 6.4 · SQL OPCIONAL — SIN EJECUTAR
-- Archivo: 20261115_0011_gp_proyectos_estado_guard_opcional.sql
-- Fecha: 2026-11-15 | Guardia anti-bypass del estado (hallazgo R-4 del paquete 6.4)
-- APLICACIÓN: OPCIONAL (decisión del responsable). Recomendada: justo tras 0010.
-- Reversión simple: DROP TRIGGER trg_gp_proyectos_estado_guard ON public.gp_proyectos;
-- ==============================================================================
-- HALLAZGO AUDITADO (paquete 6.4 · §6 R-4):
--   La política gp_proyectos_update de 0004 (L229-232) autoriza UPDATE a
--   CUALQUIER miembro de la empresa (gp_is_empresa_member) sobre TODAS las
--   columnas. Un usuario autenticado podría, por PostgREST directo, escribir
--   gp_proyectos.estado_codigo SIN pasar por la RPC 0010: sin mapa de
--   transiciones, sin motivo obligatorio y SIN auditoría.
--   La RPC es la barrera de la APP; la RLS no puede distinguir "UPDATE vía RPC"
--   de "UPDATE directo" porque no existe predicado de rol de invocación.
--
-- SOLUCIÓN NO DESTRUCTIVA (este archivo): trigger BEFORE UPDATE que bloquea el
-- cambio de estado_codigo cuando el ejecutor NO es:
--   · la vía definida del dominio (funciones SECURITY DEFINER propiedad de
--     postgres → dentro del definer current_user = 'postgres'), ni
--   · operación de plataforma aprobada (gp_is_platform_admin() = true),
--   ni un rol de administración (service_role: backfill/admin, 0100).
-- Los cambios de OTRAS columnas (nombre, presupuesto, fechas…) NO se tocan:
-- siguen gobernados por la política RLS de 0004 exactamente igual que hoy.
-- SIN DROP/TRUNCATE de datos. IDEMPOTENTE (CREATE OR REPLACE + trigger nombrado).
-- ==============================================================================

CREATE OR REPLACE FUNCTION public.gp_bloquear_estado_directo()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
  IF NEW.estado_codigo IS DISTINCT FROM OLD.estado_codigo
     AND current_user IN ('authenticated')
     AND NOT COALESCE(public.gp_is_platform_admin(), false) THEN
    RAISE EXCEPTION
      'ESTADO_VIA_RPC: el cambio de estado del proyecto debe ejecutarse con la RPC gp_cambiar_estado_proyecto (valida transición, motivo obligatorio y auditoría). Escritura directa de estado_codigo denegada.';
  END IF;
  RETURN NEW;
END;
$$;

DROP TRIGGER IF EXISTS trg_gp_proyectos_estado_guard ON public.gp_proyectos;
CREATE TRIGGER trg_gp_proyectos_estado_guard
  BEFORE UPDATE ON public.gp_proyectos
  FOR EACH ROW EXECUTE FUNCTION public.gp_bloquear_estado_directo();

-- ==============================================================================
-- VERIFICACIÓN (requiere 0002/0003/0004/0010 aplicados):
-- a) Por RPC con sesión real autorizada (gerente/admin) → cambia y audita
--    (comportamiento normal intacto: el definer corre como postgres).
-- b) UPDATE directo con un cliente AUTENTICADO no-plataforma:
--      update public.gp_proyectos set estado_codigo='completado' where id='<uuid>';
--    → ERROR 'ESTADO_VIA_RPC: …' y la transacción completa aborta (nada a medias).
-- c) UPDATE directo de OTRAS columnas con sesión autorizada por la RLS de 0004

-- d) SQL Editor (postgres) y service_role (backfill 0100) → sin interferencia.
--
-- RIESGO CONOCIDO / NOTA DE FUTURO: si algún día se aprueba una NUEVA vía

-- postgres), no requiere cambio: correrá como 'postgres'. Si en cambio se
```

## §7 · Recuperación ante errores

1. **Regla general:** cada migración se ejecuta en UNA transacción. En SQL Editor, envolver explícitamente: `BEGIN; <contenido completo del archivo>; COMMIT;`. Si algo falla a mitad: `ROLLBACK;` y la base queda EXACTAMENTE como antes (todo el DDL aquí es transaccional). Nunca continuar con el siguiente paso tras un fallo (regla del tracker 5.2).
2. **Los errores son fail-fast y explicativos por diseño:** `0008`/`0009`/`0010` llevan guardias (`RAISE EXCEPTION` con instrucción). El mensaje dice qué falta; corregir la causa (normalmente: aplicar antes la migración indicada en el mensaje) y re-ejecutar el archivo completo — todos son idempotentes.
3. **Errores esperables y su causa:**
   - `0002`/`0003` "violates foreign key constraint" → falta el catálogo referenciado ⇒ revisar que FASE 2 se aplicó completa y en orden.
   - `0003` "there is no unique constraint matching given keys" sobre `gp_roles_proyecto_c` → `0008` no se aplicó (R-2).
   - `0004` "column does not exist" al crear funciones → `0002`/`0003` incompletos.
   - `0010` §1 "faltan tabla(s) del dominio" → cadena incompleta; el mensaje lista exactamente qué falta.
   - `0010` runtime `PERMISO_INSUFICIENTE: … aplica 20261115_0008` → falta la columna `permisos` o el seed: aplicar `0008` (o re-ejecutarlo) y reintentar.
4. **Daños a datos: imposibles por diseño del paquete.** Si aun así se alterara algo a mano, restaurar desde los dumps D-2/D-3 (evidencia previa guardada en bitácora): son tablas pequeñas; la restauración manual es `INSERT … ON CONFLICT DO NOTHING` con los valores del dump. **Nunca** "arreglar" con DROP/TRUNCATE.
5. **Si `0006b` deja a la app sin acceso a unidades** (R-6, suscripción no activa): NO re-crear la política "Permitir todo" a mano. Completar la suscripción/rol (paso 1.2) y re-verificar V-06.
6. **Registro:** cada ejecución (éxito o fallo) se anota en `7-Bitacoras/` con fecha, archivo, resultado y, si hubo fallo, el mensaje íntegro.
