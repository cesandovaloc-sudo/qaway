## §4 · SQL pendiente de ejecutar (separado por migración) + verificación viva

**Orden del responsable (agente no ejecuta):**

1. **`0007`** — `3.7-SQL-propuesto-sin-ejecutar/20261114_0007_gp_prioridades_c.sql` (paquete completo `5.5`, aprobado 14-nov). **Requerido para esta integración** (crea `gp_prioridades_c` con seed `urgente/alta/media/baja` y RLS + lectura abierta).
2. **Prerrequisitos Etapa 4** (per `3.9`): `0006a` (registro `gestor-proyectos` en `app_catalog`) → `0005` (columna `orden`) → `0006b` (RLS de `gestor_unidades`).
3. **`0004`** — capa de seguridad `gp_*`: aquí nacen las políticas de **lectura** de catálogos (`USING(true)`) y la de escritura admin. Sin él: si los catálogos ya tienen RLS activa **sin** políticas, la lectura falla → la UI muestra fallback + warn (no se rompe nada).

**Query de estado real de acceso (pegar salida como evidencia):**
```sql
select c.relname as tabla, c.relrowsecurity as rls,
       coalesce(p.politicas, 0) as politicas
  from pg_class c
  join pg_namespace n on n.oid = c.relnamespace
  left join (select tablename, count(*) as politicas
               from pg_policies where schemaname = 'public'
              group by tablename) p on p.tablename = c.relname
 where n.nspname = 'public'
   and c.relname in ('gp_estados_proyecto_c','gp_tipos_proyecto_c',
                     'gp_estados_ejecucion_c','gp_prioridades_c')
 order by c.relname;
```
Interpretación: `rls=false` ⇒ legible ya (se endurecerá con 0004) · `rls=true` + ≥1 política ⇒ legible si es `FOR SELECT USING (true)` · `rls=true` + 0 políticas ⇒ **ilegible** (aplicar `0004` primero).
