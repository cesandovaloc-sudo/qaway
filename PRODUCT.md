# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Clientes y empresas que visitan el sitio para comprar los servicios y cursos de QawayLab. El visitante principal es un comprador en etapa de decisión.

## Product Purpose

QawayLab presenta y vende sus servicios y cursos de marketing y digitalización. Éxito = que el visitante convierta en compra de un servicio o curso.

## Positioning

Productos validados: QawayLab solo ofrece lo que ya fue validado con el mercado antes de lanzarlo.

## Operating Context

Sitio multi-sección con: inicio, estudio, sistemas digitales (automatización, canales digitales, webs y landings, CRM/datos/dashboards, agentes IA, estrategia digital), academy (cursos), qaway hub, recursos, blog y landings.

## Capabilities and Constraints

- Constraint explícita (etapa actual): el diseño vigente no debe modificarse ahora; esta fase es solo de validación. El modo live se usa de forma exploratoria, sin aceptar cambios de diseño.
- Stack: Vite + React 18 + Tailwind 3, dev server en puerto 4000.

## Brand Commitments

Nombre y marca: QawayLab / QAWAY LAB. El sistema visual existente es la fuente de verdad mientras no haya una decisión explícita de rediseño.

## Evidence on Hand

El sistema visual actual está implementado en el código del sitio (tokens, componentes, páginas). Sin DESIGN.md todavía; es una brecha de documentación, no una ausencia de diseño.

## Product Principles

- Validar antes de construir: no se ofrece nada que no esté validado.
- El diseño vigente se preserva; los cambios solo ocurren con autorización explícita.
- Foco en conversión: cada sección debe llevar al visitante hacia la compra de un servicio o curso.
